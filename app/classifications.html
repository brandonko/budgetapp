Classifications and actions

A classification is a reusable set of changes. It can update a transaction’s description, category, subcategory, account identity, notes, refund status, or internal-transfer treatment. Only selected actions are applied; every other transaction field stays unchanged.

Classifications are evaluated alphabetically by category and subcategory. The first matching classification wins, so each transaction is changed at most once during a classification pass.

Rules and matchers

Each rule can match the current category, subcategory, description, account name, and provider with case-insensitive regular expressions. Every populated matcher in one rule must match. Empty matchers are ignored, and multiple rules within one classification act as alternatives.

A rule note is only a reminder for you. It is never used to match a transaction. Rules run automatically during import; use Apply to existing transactions to preview and confirm the same changes for transactions already in Ledger.

Classification flow

for each transaction:
  for each classification in alphabetical order:
    for each rule in the classification:
      if every populated matcher matches the transaction:
        apply each configured classification action
        stop checking this transaction

Rules are stored in data/classifications.json.
